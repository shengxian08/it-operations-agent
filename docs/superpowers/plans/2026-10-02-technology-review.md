主应用、正式数据库、模型配置与现有索引不迁移。保留此前业务路径审查和工作区修改。

## 顺序

1. 固定现状与约束；并行核验解析器和检索模型官方材料。
2. 实现隔离实验目录与明确标签的合成 IT 语料。语料和参数在运行前固定，留出集不参与调参。
3. 执行当前 PyMuPDF 的支持/拒绝样本及命令块完整性对照；以来源为依据的结构候选保存原文与出处。
4. 在无网络、只读缓存、4 CPU / 6 GiB 的独立容器中执行固定 revision 的真实 BGE 编码；在独立 Qdrant collection 上验证向量和权限过滤。
5. 在同一语料、模型、候选数、权限和重排下比较当前加权融合与应用层 RRF；另一次只改变结构元数据上下文。分别报告融合前后和重排后结果。
6. 对预检发现的缺失资产，在独立目录尝试固定版本的公开 Qwen3-Reranker-0.6B 与 Docling 本地 CPU 路径；不上传文档，正式推理断网，保存安装/下载失败。运行已有业务一致性测试与只读四路径探针；评估现有事务/台账的适用性，不引入未证明必要的替代框架。
7. 输出两个主报告、模块决策、候选预检、复现说明和不足。独立审查实验控制、证据与结论，修正后再验收目标。

## 固定实验规则

- 所有本轮产物位于 experiments/technology_review、artifacts/technology-review、docs/architecture 和 docs/experiments；不覆盖历史审查证据。
- 受控合成数据可有完整相关性标签，但不能代表企业真实质量。现有 Markdown 文档可作为本地附加样本；不对外上传。
- 默认融合参数使用现有 0.65/0.35，候选每路 40；RRF 的 k 在运行前固定。两臂使用相同 LexicalReranker、top-5、每文档最多 2 个结果。
- 新 embedding 的向量不得写入已有 collection；模型身份、维数、语料、chunk 内容与过滤条件均保存在 manifest。
- 性能固定线程/资源，至少三次热运行报告中位数与范围；冷加载单列。没有真实答案模型时答案与引用质量保持未验证。
- 候选先预检；对许可已核验的一个 0.6B 重排模型与 Docling 所需小模型，尝试独立资产准备。下载只接收公开固定资产，推理断网，不改变主依赖/缓存。其余候选未安装/未缓存保持未运行，不宣称质量或速度。
- 成功标准是完整而诚实的技术审查与可执行部分的实验交付，不是证明“最先进”或“生产就绪”。
