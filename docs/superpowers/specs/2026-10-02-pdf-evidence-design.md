# PDF 表格证据闭环

依据用户要求与[共享对话](https://chatgpt.com/share/6abf375e-b318-83ea-bfbf-2556d572e59b)。保留现有生产实现和未提交修改，只完成本阶段独立闭环；完整业务审计另见 project-audit.md。

复现根因：正式解析使用 page.get_text() 丢失单元格关系；通用字符窗口不保留表头；_relevant_excerpt 的 240 字摘要是模型实际收到的证据。旧 PDF 测试只验关键词。

支持范围：有可靠文字层的普通段落、单页规则线框表格、单层非空且唯一表头、无合并单元格。表格数据行与全部页面文字上下文一并进入检索，每行不超过 800 字。检测到合并、无框表格、扫描内容、大面积图片或页边连续表格时拒绝发布，说明原因。未识别出的复杂布局仍需管理员与原件人工核对；不声称自动识别所有 PDF 异常。

复用 PyMuPDF 的单元格与 bbox 提取，新增独立 rag/pdf.py；生产有界子进程和旧演示导入调用相同提取器。上传任务既有 sections JSONB 保存页、表头、单元格、页坐标，不增加数据库表或服务。索引文本以页面/表格/数据行标记保存来源，按整行分块；普通长段重复页面标记。引用附 page_number/table_id/row_index/index_revision；PDF 结构化证据不经过 240 字截断。API 依据为 [PyMuPDF 官方 Page.find_tables 文档](https://pymupdf.readthedocs.io/en/latest/page.html#Page.find_tables)，实际行为由锁定本地版本和真实文件回归验证。

兼容旧索引：不删除或自动重建任何索引。pipeline_config 添加明确 extraction/chunking 与 legacy policy 身份，既有版本与新版不匹配时保持现有拒绝激活语义。新快照排除缺少逐段页出处的旧平铺 PDF，保留来源正文/记录与历史索引，管理端明确提示待重新上传、暂不可检索。相同 PDF hash 仍可重新准备解析；管理员对照原件核对后逐篇发布，不因多个旧 PDF 阻断升级。先在隔离库验证再切换正式版本；旧代码镜像可读取旧版本。既有历史 PDF 的页码不得事后猜测。

逆向审查后的规则：在内存统一旋转页坐标并保留原 rotation；已识别表格之外仍检查稳定宽列间空隙，普通词间空隙不凭 text-table 猜测拒绝；扫描检测使用页内图像覆盖并集。来源 API 按引用 index_revision 打开不可变快照，同时检查当前来源与快照权限。额外 P0 修复让人工提示依赖持久编号，有编号仅称请求已记录、待处理，无编号显示未确认；图阶段不得预先宣称已经转交。

验收：实际合成中文 PDF 的单元格结构、长表分块、扫描/合并/无框拒绝与完整上下文；真实隔离 PostgreSQL/Qdrant 上传—子进程解析—预览—发布—召回—图回答/引用—停用；模型使用记录输入的可控响应，独立标为 Mock。保存原始页、解析结构、chunk、向量点数、候选及模型上下文。未提供真实失败 PDF 或批准模型凭据，因此真实文档与真实模型质量保持未验证。

选择现有库最小修复，因为已提供布局与单元格 API。替换 Docling/Unstructured 或引入 OCR 会增加模型下载、CPU/内存和部署负担，目前没有原始样本证明这些成本必要。完整多轮查单与人工交接缺口进入后续独立任务。
