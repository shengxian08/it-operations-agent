# T05：最新可见工单进度

依据已授权的持续实施范围与当前工作区分析，员工查单必须返回最近一条当前可见的真实记录和记录时间；支持人员可查看内部记录。与 T02 的对象消歧、T03 的确认建单、T04 的人工交接分开验收。本任务不调用模型，不生成假进度。

正式评论新增 public / internal / unclassified 可见性及写入时作者角色；迁移旧记录为 unclassified，员工不可见。员工只能写公开补充，支持人员可写公开回复或内部备注、核对后改变旧记录分类。写入、分类与审计保持工单版本事务和当前账号鉴权。内部评论及其审计的时间不进入员工进度；详情和列表的更新时间按可见记录计算。

进度在锁定工单的读取事务中查询当前角色、启用状态与归属；从最新可见非空评论和白名单 created/updated 审计选择真实时间最新者，同时间按稳定 ID。审计只描述合法状态和分派变化，不输出自由 JSON。摘要清理控制字符、限制长度并标记省略；保留来源类型、ID、原可见性及原内容指纹。不用工单 updated_at 冒认公开处理时间。无记录明确说明，数据库错误继续按 unavailable 处理。

历史回答保留查询时事实，但每次 get_run、events/SSE、conversation_runs、messages、幂等 enqueue/cancel 回放都重新检查当前账号、当前工单范围、来源存在及当前可见性，同时受原快照可见性约束；来源变更或无可验证来源时整段工单回答隐藏并提示重新查询。原始持久化数据不覆盖。下一轮模型历史只保留工单查询完成占位语，避免内部工具结果经模型复述后丢失权限来源。再次查询仍从当前数据库取数。

Demo/legacy 仅本人范围，使用明确公开事件或固定 created 语义，旧未知自由 summary 不冒认公开进度。正式功能真实 PG/Redis worker/API 验收，前端与浏览器 Mock 分别留证；真实企业身份、环境、模型不由这些测试代替。

验收重点：公开/内部/未分类/空记录、最新与稳定排序、准确时区、超长与控制字符、写入权限和当前账号变化、来源改权限/删除/编辑、所有历史入口与 SSE、并发提交后再次查询、DB 错误不变成查无、员工详情无内部时间或任意 audit、桌面和窄屏分类与刷新行为。
